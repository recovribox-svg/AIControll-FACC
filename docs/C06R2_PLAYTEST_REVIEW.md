## Corrections

Pure reveal-utility buffs are recognized by native components, not a name/GUID list. They gain only the current reachable party weapon damage recovered from native before/after concealment passes. The existing concealment part's native Disable counter is retained/released exactly in a finally block; no part, buff or actor is created. Native blindness/weather/attacker sight and existing mirror-image damage factors remain. Unknown/mixed buffs retain ordinary appraisal; the hidden-enemy reveal path is unchanged. Future stealth checks, future invisibility prevention and invisibility's other combat advantages receive no new guessed bonus. Unread/absent parts do not earn a fallback reward.

The optional resource-hook contract validates every opcode and resolved member in the complete prefix/getter bodies, and rejects patched functions. It reads the live boolean per quote without calling a plugin getter or setup. This safely accommodates a cache-rewritten module only when the actual runtime body still matches. A disabled switch keeps native costs; an enabled switch cancels the native SpendResource cost. Missing settings, unknown bodies/hooks and custom event/pool costs stay fallback. Independent Judgment activation actions keep their own price. Ownership, blocklists, admission and native availability/dispatch are unchanged. Offline checks inject a settings data object and Harmony metadata without reading static Main.Settings or initializing ToyBox.

A small performance correction also avoids creating a native source context when immutable buff parts are empty; the old unknown result/valuation is retained. Reveal utility is cached per target/decision and creates no source context or weapon forecast when there is no removable miss chance. No timing/search-budget retuning is introduced.
